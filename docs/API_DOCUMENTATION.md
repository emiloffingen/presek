## Authentication

### JWT Authentication

Presek uses **JWT (JSON Web Tokens)** with **HS256** algorithm for authentication.

#### Obtaining a Token

Admin tokens are generated by the system administrator. For programmatic access:

```bash
# Admin can create tokens via the admin dashboard
# Tokens are valid for 60 minutes by default (configurable)
```

#### Using the Token

Include the JWT token in the `Authorization` header:

```bash
curl -H "Authorization: Bearer YOUR_JWT_TOKEN" \
     https://api.presek.live/api/admin/dashboard
```

#### Token Structure

```json
{
  "sub": "username",
  "iat": 1705324800,
  "exp": 1705328400,
  "jti": "unique-token-id",
  "role": "admin|user",
  "permissions": ["read", "write", "admin"]
}
```

### Static Admin Token

For script access, a static admin token can be configured via `PRESEK_ADMIN_TOKEN` environment variable:

```bash
curl -H "X-Admin-Token: YOUR_STATIC_TOKEN" \
     https://api.presek.live/api/admin/dashboard
```

⚠️ **Note**: Static admin tokens are disabled by default in production for security.

### CSRF Protection

CSRF tokens are required for state-changing operations (POST, PUT, DELETE).

#### Getting a CSRF Token

```bash
curl https://api.presek.live/api/csrf-token
```

Response:
```json
{
  "csrf_token": "CLUSTER_ID...",
  "expires_at": "2024-01-15T14:30:00Z"
}
```

#### Using the CSRF Token

Include the token in the `X-CSRF-Token` header:

```bash
curl -X POST \
     -H "X-CSRF-Token: CLUSTER_ID..." \
     -H "Cookie: csrf_token=CLUSTER_ID..." \
     https://api.presek.live/api/some-protected-endpoint
```

#### Get News Feed

Get paginated news clusters with optional filtering.

```
GET /api/news
```

**Parameters:**

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `q` | string | No | - | Search query |
| `category` | string | No | - | Filter by category (e.g., "Политика", "Економија") |
| `topic` | string | No | - | Filter by topic |
| `entity` | string | No | - | Filter by entity name |
| `subcategory` | string | No | - | Filter by subcategory |
| `country` | string | No | - | Filter by country code (MK, RS, etc.) |
| `lang` | string | No | `mk` | Language (currently only `mk` supported) |
| `sort` | string | No | `recent` | Sort order: `recent`, `hybrid` |
| `timespan` | string | No | - | Time range: `24h`, `7d`, `30d`, `all` |
| `page` | integer | No | `0` | Page number (0-indexed) |
| `page_size` | integer | No | `24` | Items per page (max: 100) |
| `fast` | boolean | No | `false` | Fast mode (text search only, no embeddings) |

|------|-------------|-----------|

| 401 | Unauthorized | Missing or invalid authentication |
| 403 | Forbidden | Insufficient permissions |
| 404 | Not Found | Resource not found |
| 405 | Method Not Allowed | HTTP method not supported |

## Pagination and Filtering

### Pagination

Most list endpoints support pagination with these parameters:

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `page` | integer | 0 | Page number (0-indexed) |
| `page_size` | integer | 24 | Items per page (max: 100) |
| `limit` | integer | 24 | Alternative to page_size |
| `offset` | integer | 0 | Starting offset (alternative to page) |

**Example:**
```bash
# Get page 2 with 50 items
curl "https://api.presek.live/api/news?page=2&page_size=50"

# Get items 100-149
curl "https://api.presek.live/api/news?offset=100&limit=50"
```

### Filtering

Many endpoints support filtering:

**Common Filter Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `category` | string | Filter by news category |
| `topic` | string | Filter by topic |
| `source` | string | Filter by news source |
| `country` | string | Filter by country code |
| `from` | date | Start date (YYYY-MM-DD) |
| `to` | date | End date (YYYY-MM-DD) |
| `timespan` | string | Predefined time range (24h, 7d, 30d, all) |
| `q` | string | Full-text search query |
| `lang` | string | Language filter |

**Example:**
```bash
# Get politics articles from the last 7 days
curl "https://api.presek.live/api/news?category=Политика&timespan=7d"

# Search for articles about elections
curl "https://api.presek.live/api/news?q=Избори"
```

### Sorting

Some endpoints support sorting:

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `sort` | string | `recent` | Sort by: `recent`, `relevance`, `popularity` |
| `sort_by` | string | - | Field to sort by |
| `sort_order` | string | `desc` | Sort order: `asc`, `desc` |

**Example:**
```bash
# Sort by relevance (for search results)
curl "https://api.presek.live/api/search?sort=relevance"

# Sort by popularity (most viewed)
curl "https://api.presek.live/api/news?sort=popularity"
```

## Best Practices

### Rate Limiting

- Implement client-side rate limiting to avoid hitting server limits
- Use exponential backoff for retries
- Cache responses when appropriate
- Respect `Retry-After` headers

### Error Handling

- Always check the `status` field in responses
- Handle different error types appropriately
- Log errors with correlation IDs for debugging
- Implement retry logic for transient errors

### Authentication

- Store tokens securely (not in code or version control)
- Refresh tokens before they expire
- Use HTTPS for all requests
- Validate token permissions before making requests

### Caching

- Cache responses based on `Cache-Control` headers
- Use ETags for conditional requests
- Implement cache invalidation when data changes

### Security

- Never expose API keys or tokens in client-side code
- Use CSRF protection for state-changing operations
- Validate all inputs before using them
- Sanitize outputs before displaying them
